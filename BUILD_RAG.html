Fundamentos • Capítulo 01

¿Qué es RAG y por qué es indispensable?

RAG (Generación Aumentada por Recuperación) es un patrón arquitectónico que otorga a un Modelo de Lenguaje (LLM) un "examen a libro abierto". En lugar de depender únicamente de su memoria paramétrica congelada durante el entrenamiento, el sistema busca primero información relevante en una base de conocimiento externa y confiable, y la inyecta en el prompt antes de generar la respuesta.

! Alucinaciones

Cuando un LLM no sabe algo, tiende a inventar datos plausibles pero falsos con total seguridad, lo cual es inaceptable en entornos legales, médicos o financieros.

⏱ Conocimiento Estático

Los modelos tienen una fecha de corte de entrenamiento. Desconocen eventos recientes, cambios de precios, nuevas normativas o actualizaciones de ayer.

🔒 Falta de Datos Privados

Un LLM público nunca vio tus contratos internos, manuales de soporte, bases de datos SQL o wikis corporativas. RAG conecta esos datos sin reentrenar el modelo.

Flujo Técnico • Capítulo 03

Arquitectura Dual: Ingesta vs. Inferencia

Todo sistema RAG se divide en dos tuberías (pipelines) independientes: una asíncrona de indexación y otra síncrona en tiempo real ante cada consulta del usuario.

Implementación • Pasos 1 y 2

Carga de Datos y Estrategias de Chunking

El 80% de los fallos en un sistema RAG ocurren por una mala extracción de datos o una división deficiente de los textos. Si partes una tabla o separas una pregunta de su respuesta, el LLM no podrá reconstruir el significado.

ESTRATEGIA A • BÁSICA

Fixed-Size Chunking

Corta el texto cada N caracteres o tokens sin importar si corta palabras u oraciones a la mitad. Rápido, pero rompe el contexto semántico.

ESTÁNDAR
ESTRATEGIA B • RECOMENDADA

Recursive Character

Intenta dividir primero por párrafos (\n\n), luego por líneas (\n) y finalmente por frases, manteniendo unidades de pensamiento intactas con overlap.

ESTRATEGIA C • AVANZADA

Semantic & Markdown

Divide documentos según encabezados estructurales (# H1, ## H2) o detectando cambios bruscos en la similitud de embeddings entre oraciones consecutivas.

🎛️ Simulador Visual: Tamaño de Chunk y Solapamiento (Overlap)

Ajusta los controles para observar cómo el solapamiento evita que se pierda contexto entre cortes.

Paso 3 • Semántica

Embeddings y Espacio Vectorial

Un Embedding traduce texto a una lista de números flotantes (ej. 1,536 dimensiones) que capturan su significado semántico. Frases con significados similares quedan geométricamente cerca, aunque usen palabras distintas.

Modelos de Embeddings Top:
  • • text-embedding-3-large (OpenAI)
  • • BAAI/bge-m3 (Open Source Multilingüe)
  • • Cohere embed-v3 / Gemini Embedding
Paso 4 • Almacenamiento e Indexación

Bases de Datos Vectoriales (Vector DBs)

Utilizan algoritmos de búsqueda aproximada de vecinos más cercanos (ANN como HNSW o IVF) para comparar millones de vectores en milisegundos filtrando por metadatos.

Qdrant Rust • Alto Rendimiento

Excelente filtrado de metadatos en tiempo real, soporte nativo para búsqueda híbrida (vectores densos + dispersos) y despliegue sencillo en Docker o Cloud.

PostgreSQL + pgvector SQL Unificado • Producción

Ideal si ya usas Postgres: evita mantener dos bases de datos sincronizadas. Permite hacer JOINs entre datos relacionales de negocio y embeddings con índices HNSW.

ChromaDB Python • Prototipado Rápido

Ligera, embebida en memoria o disco local con cero configuración. La mejor opción para desarrollo local, pruebas de concepto y aplicaciones medianas.

Pinecone & Milvus Escala Masiva (+100M vectores)

Pinecone ofrece infraestructura Serverless 100% gestionada; Milvus es el estándar distribuido Open Source para cargas masivas empresariales.

Implementación • Pasos 5 y 6

Recuperación Híbrida, Re-ranking y Prompting Seguro

ETAPA 5A Recall Alto

Búsqueda Híbrida (RRF)

Combina Búsqueda Vectorial (intención semántica) + BM25 Léxico (palabras exactas como códigos SKU, nombres propios o leyes) mediante Reciprocal Rank Fusion.

ETAPA 5B Precisión Alta

Re-ranking (Cross-Encoder)

Recupera los Top-25 candidatos y pásalos por un modelo Re-ranker (ej. Cohere Rerank o BGE-Reranker) que evalúa la relevancia real pregunta-fragmento y selecciona los Top-5 mejores.

ETAPA 6 Grounding

Generación con Citas

Inyecta los Top-5 chunks delimitados con etiquetas XML y ordena al LLM responder únicamente usando ese contexto, citando el identificador del documento.

Plantilla de System Prompt Anti-Alucinación (Producción) 
Eres un asistente técnico experto. Responde a la pregunta del usuario basándote ÚNICAMENTE en los fragmentos proporcionados dentro de las etiquetas <contexto>.

REGLAS ESTRICTAS:
1. Si la respuesta no se encuentra explícitamente en el <contexto>, responde exactamente: "No dispongo de información suficiente en los documentos proporcionados para responder a esta consulta."
2. No utilices conocimiento externo ni hagas suposiciones.
3. Cita siempre la fuente al final de cada afirmación usando el formato [Doc: {nombre_archivo}, Pág: {pagina}].

<contexto>
{fragmentos_recuperados}
</contexto>

Pipeline RAG Completo en Python

ingest_pipeline.py 
# pip install langchain-text-splitters chromadb openai pypdf
import chromadb
from openai import OpenAI
from langchain_text_splitters import RecursiveCharacterTextSplitter

client = OpenAI()
chroma_client = chromadb.PersistentClient(path="./rag_vector_db")
collection = chroma_client.get_or_create_collection(
    name="manual_corporativo",
    metadata={"hnsw:space": "cosine"}  # Similitud del coseno
)

def ingestar_documento(texto_crudo: str, nombre_archivo: str):
    # 1. Chunking recursivo respetando párrafos y oraciones
    splitter = RecursiveCharacterTextSplitter(
        chunk_size=800,
        chunk_overlap=120,
        separators=["\n\n", "\n", ". ", " "]
    )
    chunks = splitter.split_text(texto_crudo)

    # 2. Generación de Embeddings en lote (Batch)
    response = client.embeddings.create(
        model="text-embedding-3-small",
        input=chunks
    )
    vectores = [item.embedding for item in response.data]

    # 3. Almacenamiento con metadatos para trazabilidad y citas
    ids = [f"{nombre_archivo}_chunk_{i}" for i in range(len(chunks))]
    metadatas = [{"fuente": nombre_archivo, "chunk_id": i} for i in range(len(chunks))]

    collection.upsert(ids=ids, embeddings=vectores, documents=chunks, metadatas=metadatas)
    print(f"✅ Indexados {len(chunks)} fragmentos de {nombre_archivo}")
def consultar_rag(pregunta_usuario: str, top_k: int = 4) -> str:
    # 1. Vectorizar la pregunta con el MISMO modelo usado en la ingesta
    q_embed = client.embeddings.create(
        model="text-embedding-3-small",
        input=[pregunta_usuario]
    ).data[0].embedding

    # 2. Recuperación semántica (Top-K) en la Base Vectorial
    resultados = collection.query(
        query_embeddings=[q_embed],
        n_results=top_k
    )

    # 3. Construir contexto estructurado con citas de origen
    bloques_contexto = []
    for doc, meta in zip(resultados["documents"][0], resultados["metadatas"][0]):
        bloques_contexto.append(f"[Fuente: {meta['fuente']} | Fragmento #{meta['chunk_id']}]\n{doc}")
    
    contexto_unido = "\n\n---\n\n".join(bloques_contexto)

    # 4. Generación Aumentada con System Prompt estricto (Temperatura 0)
    respuesta = client.chat.completions.create(
        model="gpt-4o-mini",
        temperature=0.0,
        messages=[
            {
                "role": "system",
                "content": "Responde SOLO usando el contexto dado. Cita siempre la fuente."
            },
            {
                "role": "user",
                "content": f"<contexto>\n{contexto_unido}\n</contexto>\n\nPregunta: {pregunta_usuario}"
            }
        ]
    )
    return respuesta.choices[0].message.content
Nivel Experto • Evolución

Patrones Avanzados de RAG

01. QUERY EXPANSION

Multi-Query & HyDE

Multi-Query reescribe la pregunta del usuario desde 3 ángulos distintos. HyDE genera una respuesta hipotética ideal y usa su embedding para buscar documentos reales similares.

02. RELACIONES COMPLEJAS

GraphRAG

Combina vectores con Grafos de Conocimiento (Neo4j). Permite responder preguntas globales o multi-salto ("¿Qué proveedores afectan a los proyectos del Q3?") donde los chunks aislados fallan.

03. AUTONOMÍA

Agentic RAG

Un agente decide dinámicamente si necesita buscar en la Vector DB, consultar una API SQL, reformular la búsqueda si los resultados son pobres o responder directamente.

04. GRANULARIDAD

Parent-Document Retrieval

Indexa fragmentos pequeños (150 tokens) para una búsqueda quirúrgica, pero entrega al LLM el documento o sección padre completa (1,500 tokens) para darle contexto amplio.

Calidad Medible

Evaluación con RAGAS

"Lo que no se mide, no se mejora." El framework RAGAS evalúa la tríada del RAG usando un LLM-as-a-Judge.

1. Faithfulness (Fidelidad) Meta: > 95%

¿Todas las afirmaciones de la respuesta se derivan del contexto recuperado? (Detecta alucinaciones).

2. Answer Relevance (Relevancia) Meta: > 90%

¿La respuesta contesta directa y completamente a lo que preguntó el usuario sin irse por las ramas?

3. Context Precision & Recall Meta: > 88%

¿El Retriever encontró los fragmentos correctos y los posicionó en los primeros lugares (Top-K)?
